Notes

1. What I built, and who it's for

CampusSwap is a second-hand marketplace demo aimed at university students on a tight budget to get daily needs — furniture, textbooks, electronics, bikes and even dorm essentials. It has a mobile-friendly browse view, an item detail view, natural-language search over the catalogue, and a catalogue Q&A assistant. No sign-in is required to explore any of it.

2. What's seeded, simulated, or otherwise limited

  • The catalogue is 15 seeded listings with fictional sellers — there are no real users.
  • "Message seller" and payments are simulated; the button is disabled and labelled as such.
  • Photos are represented with emoji placeholders instead of real images.

3. AI tools and models

  • Built by submitting the assignemnt brief and API information (censored within the prompt) into claude.ai and requesting for a Python code.
  • Natural-language search embeds the catalogue and the query with openai/text-embedding-3-small via the gateway's OpenRouter-compatible route, then ranks listings by cosine similarity.
  • Catalogue Q&A retrieves the closest listings the same way, then answers with gpt-5.6-terra via the gateway's OpenAI-compatible route, grounded in only those listings.
  • If the gateway isn't configured or a call fails, search falls back to keyword matching and Q&A returns a clearly labelled simulated/error message instead of failing silently — the UI shows a badge indicating which mode produced each result.

4. What I chose not to build, and why

  • Real accounts, messaging, and payments — out of scope per the brief, and unnecessary to demonstrate the core AI features.
  • A persistent vector database — the catalogue is small and static, so an in-memory index computed once per server start was enough for this demo.

5. Known issues and unfinished parts

  • The embedding index is rebuilt from scratch whenever the server restarts, which adds a short delay to the first search after a restart.
